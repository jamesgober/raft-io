# raft-io v1.1.0

**Security release for users of the `framing` feature.**

The `framing` feature now decodes peer messages with `pack-io` 2, whose decoder
is safe on untrusted input: it never panics, and the memory it allocates is
bounded by the length of the input, not by lengths the input declares. The
protocol, the public API and the wire format are unchanged.

## Wire compatibility

The bytes on the wire are identical to raft-io 1.0. A new test,
`tests/wire_compat.rs`, encodes every message variant (including entries,
configuration entries, snapshots with membership, and boundary integers) and
compares the result against vectors written by raft-io 1.0.0, then decodes
those vectors back. A cluster can mix 1.0.x and 1.1.x nodes during a rolling
upgrade.

## What changed

- `pack-io` (feature `framing`): `1.0` to `2`.
- The derived `pack_io::Serialize` / `Deserialize` impls on the message types
  are now the pack-io 2 traits. If you call them directly through your own
  `pack-io = "1"` dependency, move it to `pack-io = "2"`. `framing::encode` and
  `framing::decode` are unchanged.
- New adversarial decode tests (`tests/hostile_decode.rs`) check the largest
  allocation made while decoding short inputs that declare huge lengths.

## Unchanged

- Protocol behaviour, public API, durable log format (`persistence`).
- MSRV 1.85, edition 2024.

## Upgrade

```toml
[dependencies]
raft-io = { version = "1.1", features = ["framing"] }
```
